## 二、生成工具的现实约束

用 AI 生成时，工具只提供 **1024×1024 / 1024×1536 / 1536×1024** 三档，**拿不到 16:9 或 16:10**。

所以流程固定为两步：

1. 生成 **1536×1024**（3:2，最高的横版档）
2. **用脚本裁成 1536×864（16:9）**

```python
from PIL import Image
im = Image.open(src).convert("RGB")
w, h = im.size
im.crop((0, 0, w, round(w * 9 / 16))).save(dst, "PNG")   # 从顶部取
```

**顺带解决水印**：AI 生成图右下角默认带「AI生成」水印，
从底部裁掉 160px（1024→864）正好连水印一起去掉。**所以「从顶部取」不只是构图选择，是必须的。**

## 三、命名规矩

```
场景图     black_page_scene_<场景>.png         例：black_page_scene_badge.png
序章图     black_page_prologue_<内容>_v1.png   例：black_page_prologue_notebook_v1.png
立绘       black_page_portrait_<人物>.png      例：black_page_portrait_xu.png
立绘变体   black_page_portrait_<人物>_<状态>.png
           状态：blur（未确认身份时虚化） / locked（未解锁）
启动图     black_page_launch_v1.png
房间       black_page_room_v1.png / black_page_room_morning_v1.png
```

**立绘是动态拼路径的**：`main.gd` 里 `"black_page_portrait_%s%s.png" % [人物id, 后缀]`。
所以**加一个人物就要给齐 3 张**（`_blur` / `_locked` / 无后缀），少一张会在运行时静默不显示。
人物 id 必须与 `people.json` 里的 key 一致。

## 五、缺口清单

### 🔴 必须做

1. **比例统一** —— 8 张 16:10 裁成 16:9（见 §一）
2. **视口决议** —— 保持 1280×800 还是改 1280×720（见 §一）

### 🟡 做了明显更好

3. **线索图（5 张，可选）**
   线索面板现在是纯文字。5 条线索各配一张特写（卡片式小图即可，不用满屏场景）
   会让「我到底查到了什么」更有实感。

4. **结局 CG（5 张，可选）**
   5 个结局目前都是纯文字收尾。设计文档 §十九 说「CG 甚至可以完全不单独制作」，
   所以这是加分项不是必需项。若要做，只需 5 张，尺寸同场景图。

### 🟢 以后再说

5. **新章节的场景图** —— 每加一个可调查的实体，就要一张对应场景图。
   加图流程见 §七。
6. **人物立绘** —— 每加一个人物要一次给齐 3 张。

## 六、每张新图的画面要求

写要求时遵守三条（这三条决定了图和游戏能不能合上）：

- **留安全边**：四周 8% 不要放关键信息——上下会被裁（COVERED），
  左右也会被裁（16:9 视口 + 16:10 窗口时）
- **不出现可读文字**：AI 生成的中文字都是糊的，别让它成为信息载体
- **第一人称视角**：画面是「主角此刻看到的东西」，不是第三人称构图

## 七、风格约定

**调子：冷、静、湿。** 参考基调是「雨夜城市 + 单个光源 + 大面积暗部」。

| 项 | 规定 |
| --- | --- |
| 光源 | **单一光源**（台灯 / 屏幕 / 灯管 / 窗外霓虹），其余落在暗部 |
| 调色 | 冷蓝青为主（`#0a1a22` ~ `#62c2dd`），暖色只作为**小面积对比**（台灯、霓虹、茶） |
| 明度 | 整体压暗，**不要把画面调亮**——游戏 UI 是深色的，亮图会顶掉字幕 |
| 风格 | 写实偏动画（semi-realistic digital painting），不要纯卡通、不要厚涂油画 |
| 视角 | 第一人称，平视或略俯 |
| **禁则** | ✗ 不出现人物正脸（除了立绘） ✗ 不出现可读文字 ✗ 不出现水印 ✗ 不做强饱和 ✗ 不做大光晕特效 |

**统一性检查**：新图放进游戏后，和 `black_page_room_v1.png` 并排看——
亮度、饱和度、透视高度三者必须能接上，否则就是出戏。

## 八、加一张图的完整流程

```
1. 生成 1536×1024（3:2）
2. 裁成 1536×864（16:9），从顶部取 —— 同时去掉右下角水印
3. 按 §三 命名，放进 assets/backgrounds/
4. 跑导入（不做这步，游戏里读到的还是旧图）：
       godot --headless --path <项目> --import
5. 接到代码上（二选一）：
   · 新场景 → scripts/black_page/scenes.gd 加常量 + TABLE 条目 + BY_ACTION 映射
   · 序章某页 → data/black_page/prologue.json 那页的 "background" 字段
6. 验收：
       python tools/audit.py
       godot --headless --path <项目> res://tests/black_page_smoke.tscn   # 期望 PASS (84 checks)
```

**第 5 步别偷懒**：图像文件放对了不等于游戏里会用它——
`scenes.gd` 的 `TABLE` 和 `BY_ACTION` 才是真正的接线处。
（本项目就出过「档案室的图早就画好了、场景表里也有，
但没有任何一条调查指向它」的情况。）
