## 2. 最终视觉方向

### 2.1 定位

**风格化手绘 2D 动漫悬疑美术。不是写实，也不是半写实照片风。**

人物、场景和图标应像同一部二维动画作品：有清楚的人工线条、概括后的形体、有限色阶和设计过的光影。
背景可以细致，但细致来自构图、线稿和色块关系，不来自照片纹理或逼真材质堆叠。

关键词：**冷、静、湿、克制、墨感、二维。**

| 维度 | 现行标准 |
| --- | --- |
| 造型 | 动漫比例与概括形体；允许适度夸张轮廓，不追求真人照片结构 |
| 线条 | 可见的手绘墨线和轻微粗细变化；背景线条可弱于人物，但不能完全消失 |
| 上色 | 赛璐璐或少层级块面阴影，渐变只用于氛围，不用空气喷枪塑造照片质感 |
| 主色 | 深海军蓝、冷青灰、墨黑；参考 `#05101A`、`#0A1A22`、`#7D909C`、`#62C2DD` |
| 强调色 | 低饱和哑金或暖琥珀，仅用于关键物、灯光和交互焦点；参考 `#E0A45E` |
| 质感 | 纸张、钢笔、雨丝、旧档案等轻量二维纹理；纹理不能覆盖轮廓和信息 |
| 光线 | 单一主光源优先；阴影形状要经过设计，不做摄影式复杂反射和皮肤高光 |
| 禁止 | 照片写实、3D 渲染感、厚涂油画、塑料皮肤、Q 版、高饱和霓虹、AI 乱码、可见水印 |

### 2.2 叙事原则

- 场景图采用玩家此刻所见的第一人称或近第一人称视角。
- 关键证据通过构图被看见，不能靠图片中的可读文字传递唯一信息。
- 对话框、人物图和导航会覆盖画面，美术必须主动给 UI 留空间。
- 身份未确认时，模糊、遮挡和构图服务推理，不能提前暴露答案。
- 同一地点的昼夜或剧情变体保持机位、主要物件和空间关系一致。

### 2.3 现有素材与目标风格的关系

仓库中的图片首先是“当前可运行素材”，不是自动获得通过的最终美术标准。
现有背景中如果出现过度写实的材质、光照或细节密度，后续应按本节逐步风格化重绘；
重绘必须按场景逐张替换和验收，不做未经接线检查的整批覆盖。

## 3. 画布与安全区

基准视口为 **1280×720（16:9）**，窗口使用 `canvas_items` 拉伸与 `expand` 宽高策略。
背景以 `TextureRect.STRETCH_KEEP_ASPECT_COVERED` 铺满，因此非 16:9 窗口会裁掉部分边缘。

基准画面中的主要遮挡区域：

- 顶栏约 58 px；
- 左侧导航约 84 px；
- 底部对话区约 280 px；
- 说话人图位于右下，约 340×460 px。

背景的核心证据和动作优先放在画面 **横向 16%～72%、纵向 10%～58%**；四周至少保留 8% 可裁安全边，
右下角不要放必须持续可见的信息。

启动页是例外：标题和菜单位于左侧约 40%，所以启动背景左侧应暗、简、低对比，主物件放在中右侧。

## 4. 资产规格

| 类型 | 新资产推荐规格 | 通道 | 关键要求 |
| --- | --- | --- | --- |
| 场景背景 | **首选 2560×1440（2K）**；AI 无法输出时降级为 **1920×1080（1K 级）**；严格 16:9 | RGB，不透明 | 全屏铺满，按第 3 节留安全区 |
| 启动背景 | 同场景背景 | RGB，不透明 | 左侧给标题与菜单留负空间 |
| 人物图 | 1024×1365，约 3:4 | 当前为 RGB 暗色底 | 右侧区域显示，脸部放在中上部 |
| 新闻照片/证物图 | 正方形或 4:3，长边至少 1024 | 按用途决定 | 缩小后仍能读出主体，不依赖图内文字 |
| UI 图标 | 256×256 | RGBA，透明 | 24～32 px 仍可辨识，四周保留透明边 |
| 图标母版 | 规则网格、单元格等尺寸 | RGBA，透明 | 只作源文件，不直接用于运行时 |

当前人物图不是透明切片，而是带暗色环境底的完整肖像卡，新人物先延续这一形式。
如果未来改成透明半身立绘，必须同步重做全部角色变体，并调整叠图、描边和明暗；同一界面不能混用两套标准。

本文中的“2K”和“1K 级”专指上表的 `2560×1440` 与 `1920×1080`，不使用其他行业口径。
仓库内已有的 1526×858、1536×864、1672×940 图片是遗留可运行素材，可以继续使用，
但不再作为新增场景图的交付尺寸。

### 4.1 人物三档状态

人物图鉴按身份确认度动态加载：

```text
black_page_portrait_<id>_locked.png   身份 < 50
black_page_portrait_<id>_blur.png     身份 50～99
black_page_portrait_<id>.png          身份 = 100
```

三张图保持同一构图、尺寸和人物位置，只改变可识别程度。人物 `id` 必须与
`data/black_page/people.json` 一致。新闻照片等特例不参与动态路径。

### 4.2 UI 图标

图标路径由 `scripts/black_page/ui_style.gd` 的 `ICON_TEXTURES` 集中管理。
业务脚本只传“案件、人物、口袋、黑页、保存”等语义，不直接写 PNG 路径。
资源不可用时回退到程序化线框图标。

图标必须做到：

- 轮廓先于细节，小尺寸下仍能理解语义；
- 同组视觉重量、笔画粗细和留白一致；
- 不使用文字、数字、方形底板、外发光或投影；
- 默认状态能在深色背景上读清，悬停提亮后不丢失哑金细节。

文件映射见 [`assets/ui/README.md`](../assets/ui/README.md)。

```text
assets/backgrounds/
  black_page_launch_v<版本>.png
  black_page_room_<变体>.png
  black_page_prologue_<内容>_v<版本>.png
  black_page_scene_<场景>.png

  black_page_portrait_<人物id>.png
  black_page_portrait_<人物id>_blur.png
  black_page_portrait_<人物id>_locked.png

assets/ui/
  black_page_ui_icons_sheet_v<版本>.png
  icons/<语义名>.png
```

文件名只使用小写 ASCII、数字和下划线。不要使用“最终版”“新版”“改2”等名称；
需要保留源版本时用 `v1`、`v2`，运行时路径变化必须同步代码引用。

## 7. 已知问题与生产优先级

### P0：制作前必须处理

1. **许妍正面展示约束已落地**：通用说话人识别明确跳过 `xu`，序章只通过聊天、来电画面和声音呈现她；
   在完整大纲允许正面展示前，不得删除这条表现层约束。
2. **人物图格式已纠正**：现有文件是 RGB 暗底肖像。除非安排整体迁移，不再要求新增角色提交透明 PNG。
3. **非写实风格复核**：现有背景和人物逐张检查照片感、复杂材质和过度真实光影；不符合第 2 节的列入重绘，
   但不在替代图完成前删除当前可运行素材。

### P1：纵向切片增强

1. 为会参与核对、拼合或质询的重要线索制作证物图。
2. 评估五个结局是否需要独立 CG；没有 CG 也要定义最终画面和字幕构图。
3. 新增序章分镜时优先复用现有机位；确需新图时，先补剧情节点和场景登记再生成。

### P2：完整章节生产

第二、三章和终章必须从 `黑页_完整剧情大纲.md` 的实际场景与演出节点拆单。
每张图写清剧情节点、玩家视角、关键物、遮挡区、昼夜、变体和接入动作；
不要按旧大纲的章节标题预先批量生图。

## 8. 生产与接入流程

### 8.1 背景或剧情插图

1. 从当前剧情节点写需求卡，明确用途、视角、关键物和 UI 安全区。
2. 优先生成或绘制 2560×1440；AI 工具无法输出时使用 1920×1080。禁止用非 16:9 图片直接拉伸成交付图。
3. 人工修正手部、透视、重复物和乱码，并把照片感改成统一的二维线稿与块面上色。
4. 裁成严格 16:9；未裁切源文件保存在仓库外的可追溯素材库。
5. 按命名规则放入 `assets/backgrounds/`。
6. 在 `scenes.gd` 登记并配置动作映射；启动页、房间等特例修改对应入口。
7. 执行导入、自动测试和至少一次可见窗口人工验收。

### 8.2 人物图

1. 确认角色是否允许正面出现，以及当前剧情阶段的身份可见度。
2. 用同一定妆基准制作正常、`blur`、`locked` 三档，不分别生成构图不同的图片。
3. 核对人物 `id` 与 `people.json`，再按第 5 节命名。
4. 在右下 340×460 显示区域检查脸部、肩线和字幕遮挡。
5. 验证身份值 0、50、100 三个边界。

### 8.3 UI 图标

1. 先定义语义键，再生成或绘制；不用最终中文按钮文案作文件名。
2. 母版拆分后统一为 256×256 RGBA，清理低透明度杂点。
3. 在 `ui_style.gd` 的 `ICON_TEXTURES` 登记，不在业务页面重复加载路径。
4. 检查默认、悬停、按下、禁用状态，以及 24、27、34 px 三种尺寸。

## 9. 验收清单

### 通用

- [ ] 用途对应当前剧情节点或 UI 语义，不来自已过期大纲。
- [ ] 画面是风格化手绘 2D 动漫，不是写实、半写实照片风或 3D 渲染风。
- [ ] 场景底图严格为 16:9，优先 2560×1440，降级时为 1920×1080。
- [ ] 文件名、目录、尺寸和通道符合第 4、5 节。
- [ ] 无水印、乱码、明显生成瑕疵和版权来源不明内容。
- [ ] 与房间夜景、现有人物和 UI 图标并排时，色温、线条和明度属于同一世界。
- [ ] 关键内容未落入裁切区、顶栏、导航、字幕或人物遮挡区。

### 工程

```bash
godot --headless --path . --import
python tools/audit.py
godot --headless --path . res://tests/black_page_smoke.tscn
```

- [ ] Godot 导入无脚本错误或资源错误。
- [ ] `tools/audit.py` 退出码为 0；素材池与图标母版的未引用提示已人工确认。
- [ ] 冒烟测试输出 `BLACK_PAGE: PASS`；不把检查数量写进规范，因为数量会增长。
- [ ] 在 1280×720、宽屏和较窄窗口各检查一次裁切与 UI 遮挡。
- [ ] 图标和文字在常用缩放下可辨识。

## 10. 来源与维护

- AI 辅助素材在外部素材台账记录工具/模型、日期、提示词、参考图来源和人工修改。
- 第三方素材保留原始地址、作者和许可证；音频继续维护在 `assets/audio/CREDITS.md`。
- 每新增、替换、接入或退役一项视觉资源，同步更新第 6、7 节。
- 删除前确认没有代码引用、剧情计划和存档用途；未定资源优先放入明确素材池。
- 整体迁移视觉标准时提高母版版本并写明范围，不让同一界面长期混用两套画风。
