# 《黑页》核心玩法与系统策划案 V0.2

## 1. 游戏核心定义

《黑页》是一款 3～5 小时的现代都市悬疑调查游戏。

玩家拥有一本可以杀人的笔记本。

但游戏真正的核心不是"杀人"，而是：

> **在有限时间里调查一个人，确认他的真实身份，了解他做过什么，然后决定是否写下他的名字。**

所有系统最终都服务于三个问题：

### 他是谁？
由"身份确认"系统回答。

### 他做了什么？
由"案件、线索、真相"系统回答。

### 我要不要杀他？
由玩家自己回答。

游戏不告诉玩家正确答案。

---

# 2. 玩家完整体验流程

玩家大部分时间会在一个"调查中心界面"进行操作。

正常流程如下：

```text
进入新的一天
↓
新闻 / 短信 / 剧情事件发生
↓
案件更新
↓
玩家打开案件界面
↓
查看当前疑点
↓
选择调查行动
↓
消耗一次行动次数
↓
发生调查剧情 / 对话 / 小游戏
↓
获得线索
↓
更新案件 / 人物 / 身份 / 真相
↓
可能解锁新的案件
↓
玩家决定继续调查
或
打开笔记本
↓
写下名字 / 放弃书写
↓
进入下一时间段
↓
世界产生后果
↓
下一天
```

整个游戏始终围绕这个循环进行。

---

# 3. 主界面

## 3.1 基础视觉

玩家的主要场景是主角的房间。

时间主要发生在晚上。

整体风格：

现代都市。

冷色。

雨夜。

电脑光。

手机通知。

极简UI。

黑色笔记本是画面中最特殊的物体。

主界面可以采用：

左侧功能栏。

中央场景画面。

右侧信息区域。

底部剧情文本。

---

## 3.2 左侧四个核心按钮

整个正式游戏只突出四个主要系统：

### 案件

查看当前所有事件。

### 人物

查看调查过的人。

### 线索

查看已经获得的信息。

### 黑页

打开死亡笔记。

玩家基本不需要学习更多主菜单。

---

## 3.3 顶部信息

顶部只显示：

```text
第 3 天    18:40

今日行动：2 / 3
```

不要显示大量数值。

像：

警察怀疑值72

玩家侵蚀值54

全部隐藏。

玩家应该通过人物态度和剧情表现判断。

---

# 4. 时间系统

## 4.1 基础结构

每一天分为：

上午

下午

晚上

玩家拥有：

**3次调查行动。**

每进行一次重要调查：

时间推进一个阶段。

例如：

上午调查医院。

下午询问证人。

晚上查阅档案。

第三次行动完成后进入夜晚结算。

---

# 5. 每日结算

一天结束时自动处理世界事件。

例如：

嫌疑人逃跑。

证人失踪。

新闻更新。

警方开始调查。

某人物死亡。

某证据被销毁。

某NPC主动联系玩家。

玩家前一天使用笔记本：

也通常在这里得到死亡反馈。

这样玩家的决定不会马上得到结果。

能够制造等待和不安。

---

# 6. 限时事件

部分事件拥有隐藏期限。

例如：

【王晨】

明天离开城市。

玩家如果今天不调查：

第二天人物状态变成：

> 已离开。

对应调查路线消失。

但是不会Game Over。

玩家可能通过其他案件再次获得相关信息。

所以时间系统的作用不是：

逼玩家完美规划。

而是：

> **让玩家不能无限调查到100%以后再做决定。**

---

# 7. 案件系统

案件是玩家理解游戏世界的第一层结构。

例如：

```text
许妍失踪案

状态：
调查中

已知：
许妍于23:38离开便利店。
23:46出现在公交站。
监控中出现一名男性。

当前问题：

许妍去了哪里？

监控里的男人是谁？

二人是否认识？

可调查方向：

调查公交站监控

询问许妍室友

调查"陈东"
```

---

# 8. 案件不是任务列表

不要设计：

```text
任务：
找到3条证据 2/3
寻找陈东 0/1
```

这样会失去悬疑感。

案件页面应该更像：

**玩家的调查笔记。**

呈现的是：

已经知道什么。

还不知道什么。

而不是：

距离完成还差多少。

---

# 9. 案件状态

一个案件内部可以存在：

### 未发现

玩家不知道案件存在。

### 调查中

已经出现。

### 暂无调查方向

当前线索断裂。

未来可能再次更新。

### 真相基本明确

主要事实已经获得。

### 冻结

因为人物死亡、证据销毁等原因暂时无法继续。

不要出现传统意义上的：

> 完成100%。

因为旧案件可以被新线索重新解释。

---

# 10. 案件交叉

这是游戏非常重要的特点。

例如：

```text
许妍失踪案
↓
发现陈东身份异常
↓
晨曦福利院火灾
↓
获得周文远旧照片
↓
更新陈东人物档案
↓
重新更新许妍失踪案
```

玩家调查B案件，

实际可能推进A案件。

所以案件不是独立关卡。

而是一张网。

---

# 11. 人物系统

人物系统负责回答：

> 这个人是谁？

以及：

> 我们现在知道他多少？

玩家打开人物页面：

```text
陈东

年龄：
约32岁

职业：
恒远物流员工

真实姓名：
？

状态：
下落不明

关联案件：
许妍失踪案
晨曦福利院案

身份确认：
■■■■■■■□□□

真相掌握：
■■■■□□□□□□

笔记本：
无法确认
```

---

# 12. 身份确认度

身份确认度本质上表示：

> 玩家当前掌握的信息是否足够准确地指向这个具体的人。

影响身份确认的线索例如：

身份证。

出生记录。

旧照片。

DNA资料。

学校档案。

亲属证词。

工作记录。

身体特征。

---

# 13. 身份确认不是一直增加

这是一个重要机制。

例如：

玩家最初获得：

身份证"陈东"。

身份确认：

70%。

后来发现：

身份证八年前才注册。

之前完全没有这个人的记录。

系统：

70%

↓

52%

提示：

> 当前身份存在异常。

调查不是经验值升级。

新证据可能推翻旧结论。

---

# 14. 真相完整度

真相完整度回答：

> 玩家对这个人物与当前事件了解多少。

相关内容包括：

动机。

经历。

与受害者关系。

过去行为。

是否说谎。

是否真正犯罪。

为什么出现在现场。

---

# 15. 身份和真相必须完全独立

例如：

### 人物A

身份确认：

100%

真相：

25%

意味着：

> 你完全知道他是谁。

> 但你根本不知道他做了什么。

笔记本：

**可以使用。**

---

另外一个人物：

身份确认：

45%

真相：

85%

意味着：

> 你几乎确定他是凶手。

> 但不知道他的真实姓名。

笔记本：

**无法稳定使用。**

这就是游戏最核心的张力。

---

# 16. 人物状态

每个人还拥有一个世界状态：

正常。

失踪。

逃亡。

受伤。

死亡。

被捕。

隐藏。

离开城市。

人物状态直接影响：

可调查内容。

剧情选项。

其他人物。

案件结果。

---

# 17. 线索系统

线索是所有系统之间真正的"货币"。

玩家调查得到的不是：

经验值。

金币。

技能点。

而是：

**信息。**

---

# 18. 线索类型

第一版可以只需要：

照片。

证词。

文件。

聊天记录。

新闻。

录音。

视频。

身份记录。

医疗资料。

物证。

---

# 19. 一条线索可以同时影响多个系统

例如：

### 【晨曦福利院旧合照】

获得后：

解锁福利院案件新内容。

陈东身份确认 +15。

发现"周文远"。

解锁调查方向：

寻找福利院幸存者。

更新人物关系：

陈东 ←？→ 周文远。

所以线索不只是图鉴。

它本质上是：

> **推动世界状态改变的核心对象。**

---

# 20. 线索可信度

部分线索可以存在：

可靠。

存疑。

矛盾。

伪造。

例如：

某证人说：

> "我亲眼看到沈医生给病人注射药物。"

这是：

【证人证词】

但后来监控证明：

当晚沈医生根本不在医院。

该线索状态：

可靠

↓

矛盾。

玩家会发现：

以前得到的信息不一定是真的。

---

# 21. 关系网

玩家可以进入"案件关系图"。

初期：

```text
许妍
  │
  ↓
陈东
```

调查后：

```text
           晨曦福利院
               │
               ↓
许妍 ───── 陈东 ───── 周文远？
 │             │
 │             ↓
父亲 ──── 恒生生物
```

不需要玩家手动拖线。

系统根据线索自动产生。

主要作用：

帮助玩家理解复杂关系。

---

# 22. 调查行动系统

玩家在案件中点击一个调查方向：

例如：

> 调查陈东住所。

点击以后：

提示：

```text
预计消耗：
1次行动

前往调查？
```

确认后进入调查剧情。

---

# 23. 调查内容的四种形式

为了控制开发量，第一版调查主要采用四种表现。

## 对话调查

和NPC交谈。

玩家选择询问内容。

不同选项获得不同信息。

---

## 场景调查

显示一个场景背景。

例如：

办公室。

医院。

福利院。

公交站。

玩家点击几个关键交互点。

---

## 文件调查

查看：

档案。

电脑。

聊天。

新闻。

病历。

玩家从中寻找矛盾信息。

---

## 小游戏

只用于关键剧情。

例如：

还原监控。

匹配两张照片。

恢复录音。

整理时间顺序。

第一版控制在2～3个。

---

# 24. 调查结果

每次调查结束后系统统一结算：

```text
获得线索：

【公交站监控】

人物更新：

陈东
真相 +8

案件更新：

许妍失踪案
发现新的调查方向：

【调查出租车】
```

然后玩家回到主界面。

---

# 25. 笔记本系统

笔记本是独立界面。

打开后其他UI全部淡出。

只显示一本真正的笔记本。

声音变得非常安静。

---

# 26. 选择目标

左页显示：

```text
选择目标
```

列出玩家已经调查过的人物。

例如：

沈清河

身份确认：100%

周文远

身份确认：82%

林墨

身份确认：100%

但并不意味着所有人都应该杀。

---

# 27. 查看目标

选择沈清河：

左页：

照片。

姓名。

身份确认：

100%

右页：

```text
当前掌握真相：
46%

相关案件：
医院异常死亡案

状态：
可书写
```

系统不会显示：

"建议继续调查。"

因为游戏不能替玩家做道德判断。

---

# 28. 身份不足时书写

如果身份确认只有：

75%。

玩家仍然可以尝试输入名字。

但笔记本可能：

没有反应。

名字被划掉。

页面留下永久痕迹。

甚至出现其他未知结果。

第一版最简单可以设计：

身份低于某阈值：

无法稳定生效。

身份越接近100%：

成功率越高。

但不要直接显示概率。

---

# 29. 写下名字

确认以后：

界面停止音乐。

播放笔尖声音。

玩家输入或者选择：

> 沈清河

系统再次确认：

```text
一旦写下，
无法撤销。
```

按钮：

【落笔】

【合上笔记】

点击落笔。

名字写入。

笔记合上。

不会立即显示：

目标死亡。

---

# 30. 死亡反馈

几小时或者第二天：

手机新闻：

> 沈清河医生昨夜于家中突发心脏骤停。

人物状态：

正常

↓

死亡。

随后触发世界变化。

---

# 31. 死亡带来的连锁反应

沈清河死亡可能导致：

医院停止接受调查。

他的私人文件无法通过本人获得。

某个知情者因为害怕主动联系玩家。

警方开始注意异常死亡。

恒生生物认为威胁被解除。

从而开放另一个调查机会。

所以：

> 杀一个人不是删除一个NPC。

而是重新排列整个案件网络。

---

# 32. 世界状态系统

这个系统不需要直接展示给玩家。

它记录游戏当前世界到底变成了什么样。

例如：

```text
沈清河 = dead

周文远 = missing

许妍 = hidden

医院资料 = destroyed

林墨信任 = medium

林墨怀疑 = high
```

所有剧情节点都可以根据这些状态产生不同内容。

---

# 33. 林墨系统

林墨是整个游戏里最重要的长期NPC。

玩家与他存在两个隐藏状态：

### 信任

代表：

他是否愿意帮助玩家。

### 怀疑

代表：

他是否认为玩家与死亡案件有关。

注意：

两个值可以同时很高。

例如：

林墨非常相信玩家是个好人。

但同时非常怀疑：

玩家知道某些事情。

这种状态比单一好感度更有意思。

---

# 34. 林墨信任的影响

高信任：

分享警方内部信息。

透露尸检结果。

允许玩家查看部分档案。

主动警告危险。

低信任：

拒绝回答。

隐藏调查内容。

不给玩家接触证据。

---

# 35. 林墨怀疑的影响

低：

普通合作关系。

中：

开始问：

> "你为什么总是在现场附近？"

高：

调查玩家行动记录。

极高：

跟踪主角。

检查主角住所。

最终可能：

发现笔记本。

---

# 36. 玩家失败

第一版重点采用：

### 软失败。

而不是频繁Game Over。

---

# 37. 杀错人

例如：

玩家过早杀死沈清河。

后面发现：

他并不是实验负责人。

结果：

部分真相永久无法获得。

其他人物态度改变。

游戏继续。

---

# 38. 错过时间

没有及时调查证人。

第二天：

证人失踪。

对应线索失去。

但是可能存在另一条更困难路线。

游戏继续。

---

# 39. 身份调查错误

玩家相信伪造身份。

笔记本书写失败。

或者产生错误结果。

游戏继续。

---

# 40. 调查路线断裂

例如：

关键人物死亡。

文件被销毁。

主线不会彻底卡死。

必须始终保证：

至少存在一条低信息量路线能够推进最终剧情。

区别只是：

玩家知道多少真相。

---

# 41. 真正硬失败

只放在非常严重的情况。

例如：

警方掌握决定性证据。

林墨发现笔记本。

主角被控制。

所有关键调查线同时断裂。

进入特殊坏结局。

而不是传统：

GAME OVER。

---

# 42. 案件主线设计

第一版主要三个案件：

## 案件A

许妍失踪案。

玩家最初以为：

陈东绑架许妍。

---

## 案件B

晨曦福利院火灾。

作用：

发现陈东真实身份。

确认：

陈东可能就是周文远。

---

## 案件C

医院异常死亡案。

作用：

引出恒生生物。

让玩家第一次面对：

身份完全确认，

但真相完全不明确的人。

---

# 43. 三案关系

真正结构：

```text
十三年前

晨曦福利院
↓
恒生生物秘密项目
↓
周文远失踪
↓
获得"陈东"身份


三年前

许妍父亲
↓
发现恒生生物秘密
↓
离奇死亡
↓
资料交给许妍


现在

许妍被追查
↓
周文远出现
↓
许妍失踪
↓
主角开始调查
```

医院案件则从侧面证明：

恒生生物的问题仍然存在。

## 主角定位与首案触发

主角：第一人称，**没有名字、没有独立人物档案**（维持原设计）。

**许妍 = 主角的前任。**

序章已经完成的设定：你收到一个无名纸盒，里面是一册黑色笔记本；你写下「高启明」，
次日他心脏骤停死亡。**这就是主角的全部底牌**——一个普通人，手上有一本不该存在的笔记本，
而且已经用过一次。不再补身世。

首案为什么来：上面这条证据链断在「**许妍接手的资料，现在在哪**」。
答案：**一份在主角手里**——许妍失踪前几天，以「帮我保管一下」为由交给了主角。

于是：

```text
许妍失踪
↓
林墨查她的通讯记录
↓
最后联系过她的人里有主角（前任，天然成立）
↓
林墨上门 —— 他不是来请你帮忙的，是来查你的
```

这一段同时解决四件事：

1. **为什么是这个案子** —— 她和主角有关，不是随机掉下来的
2. **为什么是现在** —— 她刚失踪，主角手上的东西突然变成关键
3. **为什么林墨会给资料** —— 不是结盟，是试探
   （对应他的人物描述「愿意听你说，但一直在观察你怎样回答」）
4. **为什么主角不能说实话** —— 来源是笔记本，说出去要么是疯子，要么是嫌疑人
   （现有行动「向林墨交代调查来源」的张力就落在这里）

**触发点**：序章结束 → 回到房间 → 手机上出现林墨的消息，桌上多了个还没拆的信封。
侧栏「案件」从空列表变成许妍失踪案。

主角还没拆的那个信封，里面就是案件B（福利院）与案件C（恒生生物）的种子——
三个案子靠一件实物串起来，不必再额外编动机。

# 46. 人物图鉴

## 它和「案件 / 口袋 / 黑页」的分工

| 系统 | 管什么 |
| --- | --- |
| 案件 | 正在查的事：已知什么、还不知道什么、可查的方向 |
| **人物图鉴** | **你调查过的人**：肖像、身份确认、真相掌握、逐条解锁的档案 |
| 口袋 | 这次调查拿到手的东西 |
| 黑页 | **只做一件事：写下名字** |

黑页不再显示身份 / 真相——那些都归图鉴，避免两个地方说同一件事。

## 解锁规则：不新增旗标，全部从现有状态推导

图鉴的"部分内容锁着"是**推导出来的**，不另设一套 `unlocked` 开关，否则两套真相一定会脱节。

**肖像清晰度 ← `person.<id>.identity`（身份确认 %）**

| 身份确认 | 肖像 |
| --- | --- |
| < 50 | 重模糊 + 压暗（还不知道这人长什么样） |
| 50 ~ 99 | 轻模糊（见过，但说不准） |
| = 100 | 清晰 |

**档案条目 ← `person.<id>.truth`（真相掌握 %）**，每条档案带一个 `at` 阈值，
`truth >= at` 才展开；没到的只显示条数（「还有 N 条尚未确认。」）。

**关联线索 ← `clues.json` 里每条线索的 `people` 字段**（零新数据）。

## 数据：`data/black_page/codex.json`

```json
{
  "zhou": {
    "entries": [
      { "at": 0,  "title": "公交站的男人", "text": "……" },
      { "at": 8,  "title": "叫「陈东」的人", "text": "……" },
      { "at": 15, "title": "只有八年的履历", "text": "……" },
      { "at": 85, "title": "周文远", "text": "……" }
    ]
  }
}
```

**阈值必须按真实可达值定。** 现在数据里真相值只有这几档：

| 人物 | truth 路径 |
| --- | --- |
| 陈东 / 周文远 | 0 → 8（监控）→ 15（旧档案）→ **85**（证词，或走兜底路线的 40） |
| 许妍 | 10 → 85（证照） |
| 林墨 | 30，**全程不变** |

所以周文远的档位是 `0 / 8 / 15 / 85`。
走兜底路线（truth=40）时**永远解锁不到 85 那一条**——「周文远」这一页就看不到。
这是设计上想要的效果：**没查到真相，就永远不知道他是谁。**

林墨的图鉴**永远只有两条**，对应他「愿意听你说，但一直在观察你」——
三个角色里唯一一个你看不透的人。

# 47. 场景转场（可配置）

转场写在 `data/black_page/transitions.json`，**不写死在代码里**：

```json
{
  "default": { "kind": "fade", "out": 0.26, "in": 0.42, "color": "000000" },
  "scenes":  { "notebook": { "kind": "cut" } },
  "actions": { "photo": { "kind": "fade", "out": 0.6, "in": 0.9 } }
}
```

**覆盖优先级：单条行动 > 目标场景 > 全局默认。** 三种 `kind`：

| kind | 效果 |
| --- | --- |
| `cut` | 不转场，直接换 |
| `fade` | 压黑 → 换图 → 亮回来（默认） |
| `slide` | 色板从右边扫进来、换图、继续向左扫出去 |

转场期间遮罩吃住输入，免得玩家在黑屏上看不见的时候把剧情点过去。
目标场景和当前相同时直接返回——所以「序章结束回房间」不会白闪一下。

# 48. 对话立绘

说话时在旁边显示人物立绘。**判定方式：这一句以「人物名：」开头**就显示那个人的立绘，
认不出来（比如「经办人说：……」这种一次性路人）就不显示。

立绘复用图鉴的肖像文件，所以它同样吃「身份确认 %」那套清晰度分档。

# 49. 隐藏变量：侵蚀

不要一开始做：

大量小游戏。

华丽UI。

十几个案件。

# 58. 最重要的设计原则

整个项目以后增加任何系统，都需要问一个问题：

> **它有没有加强玩家做判断的过程？**

如果没有：

就可以删。

例如：

装备系统。

等级系统。

技能树。

战斗系统。

复杂货币。

都没有必要。

这个游戏真正需要的只有：

**信息。**

**时间。**

**判断。**

**后果。**

# 59. 最终核心体验

玩家最开始：

> "我要找到这个坏人的名字。"

然后：

> "等等，这好像不是他的真名。"

接着：

> "原来他和另一个案件有关。"

继续：

> "好，我终于知道他的真名了。"

笔记本：

> 目标已确认。

玩家准备写。

但新的线索出现。

玩家：

> "等等。"

最终游戏真正想制造的瞬间就是：

> **玩家已经拥有杀死一个人的能力，却主动把鼠标从"落笔"按钮上移开。**

如果这个瞬间成立，

《黑页》的核心玩法就成立了。
