# 优化任务台账

> 本文档用于记录可选的工程优化建议、预期收益和决策状态。**列入台账不代表已批准，也不代表会自动执行。** 只有项目负责人明确批准的任务才进入实现；待决策任务仅作记录。

## 如何维护（增删查改）

- **新增**：在“任务列表”增加一行，分配不重复的 `OPT-编号`，并在“任务详情”补上收益、成本、风险、依据和验收标准。
- **查询**：按 ID、状态、建议优先级或领域筛选任务列表；详情中的“依据”提供对应文件和当前观察。
- **修改**：保留 ID，更新任务字段和详情；状态或方案发生变化时，在“决策记录”写明日期与原因。
- **删除**：可直接删除任务行及对应详情。若希望保留审计轨迹，可改为“已拒绝”或“已归档”，并记录原因。
- **执行**：负责人明确批准后，才将状态改为“已批准”。实现者不得仅因任务被记录或标为建议优先级就开始改代码。

### 状态定义

| 状态 | 含义 |
| --- | --- |
| 待决策 | 仅是候选项；尚未授权实施 |
| 已批准 | 负责人明确同意，可安排实施 |
| 执行中 | 已开始实施 |
| 已完成 | 已实现并达到验收标准 |
| 已拒绝 | 已决定不做，保留决策记录 |
| 已归档 | 暂不处理或被其他任务替代 |

### 估算口径

- 收益：高 / 中 / 低，描述预期改善，不代表保证结果。
- 成本：低（局部小改）/ 中（需调整多个模块或补验证）/ 高（跨层改造或迁移方案）。
- 建议优先级只是供负责人排序的参考，最终由负责人决定是否做、何时做。

## 任务详情

### OPT-001 — 逐步拆分主界面脚本

- **现状 / 依据**：`scripts/black_page/main.gd` 同时包含界面构建、页面切换、输入处理和剧情展示等职责，后续页面增加时修改范围会扩大。
- **预期收益**：降低页面之间的耦合，让 UI 改动更容易定位、审查和测试。
- **成本 / 影响**：中。需要渐进迁移并验证既有流程；一次性重写会带来不必要的回归风险。
- **不做的代价**：脚本继续增长后，职责边界和回归定位可能更困难；当前尚无立即故障。
- **建议验收**：至少一个高内聚页面职责迁至独立场景或控制器；原有输入、导航、剧情流程通过验证；不改变现有游戏状态写入边界。
- **执行边界**：获批后按小步拆分，不默认授权全面重构。

### OPT-002 — 存档迁移与失败恢复

- **现状 / 依据**：`scripts/core/save_manager.gd` 当前有存档 schema 版本；版本不匹配会拒绝加载，尚无迁移链。垂直切片阶段可以接受。
- **预期收益**：剧情数据和存档结构演进时，降低旧存档无法继续使用的风险。
- **成本 / 影响**：中。需要定义迁移策略、旧格式测试样例，以及迁移失败时的恢复行为。
- **不做的代价**：未来改动存档结构或内容标识后，玩家旧档可能不能直接载入。
- **建议验收**：至少支持从上一个存档版本迁移到当前版本；迁移失败不覆盖原存档；有自动化测试覆盖成功、未知版本和损坏存档。
- **建议时机**：面向外部测试者发放存档后，或首次进行破坏兼容性的存档变更前。

### OPT-003 — 按变更域刷新 UI

- **现状 / 依据**：`scripts/black_page/main.gd` 中通用 `refresh()` 会更新多个 HUD / 导航相关 UI；随着状态变化和页面增加，可能出现不必要的刷新。
- **预期收益**：让状态变化与 UI 更新范围更清晰，减少不相关控件重复更新。
- **成本 / 影响**：中。需要明确刷新域或变更事件；拆分过细也会提高维护复杂度。
- **不做的代价**：主要是将来扩展时的更新耦合；当前没有确认的卡顿或性能瓶颈。
- **建议验收**：局部状态变化只刷新相关区域；完整页面切换仍正确；必要时记录刷新次数或用性能工具验证收益。
- **建议时机**：出现可复现的刷新问题、性能数据支持，或 UI 页面数量显著增长时。

### OPT-004 — 评估状态事务的复制与校验次数

- **现状 / 依据**：`scripts/services/game_state.gd` 的效果事务会准备并验证候选状态，再经恢复流程进行校验 / 复制；当前状态规模很小，稳健性优先。
- **预期收益**：若状态数据显著增长并被证明是热点，可减少不必要的复制与重复校验。
- **成本 / 影响**：低至中。内部提交流程若改错，可能削弱事务原子性或校验完整性。
- **不做的代价**：现阶段预计影响很小；不应为理论上的性能收益牺牲健壮性。
- **建议验收**：先有可复现的基准数据；调整后事务失败仍不污染原状态；相关类型和范围校验保持完整；基准结果有改善。
- **建议时机**：只有性能测量显示该路径值得优化时。

### OPT-005 — 确认未使用的剧情 Flag

- **现状 / 依据**：架构审计提示 `data/black_page/flags.json` 中的 `prologue.package_received` 有写入但未发现读取。
- **预期收益**：清除无效数据或补充设计说明，减少策划对 Flag 实际效果的误解。
- **成本 / 影响**：低。若它是未来分支预留，过早删除会丢失约定。
- **不做的代价**：保留未使用项会带来轻微的数据噪声，不影响当前运行。
- **建议验收**：确认剧情设计用途；若确实无用途再删除，并通过数据审计；若保留则在 Flag 描述或剧情文档中注明预期用途。
